# 腾讯 Marvis 拆解（视觉与产品参考）

> 调研输入，对应 09（可视化）与 08（编排）。核心结论：Marvis 不是企业级「AI 数字员工」平台，而是**腾讯应用宝团队**做的「操作系统级个人 AI 管家」；但「卡通角色坐工位办公」的办公室 UI 确实存在，官方叫「Marvis 办公室」。

## 一、是什么（事实）

- **团队**：腾讯应用宝团队。
- **形态**：桌面端为主（Windows/macOS）+ 手机端协同，无网页版。PC 是执行宿主，手机可远程看屏幕并接管。
- **核心**：自然语言操控整台电脑——文件语义检索、系统设置与排障、网页抓取与应用操作、定时任务、跨端远控。
- **上线**：2026-05-21 正式发布，免邀请码。
- **定价**：当前完全免费，每日约 1000 万–2000 万 Token 额度。官方称「长期完全免费不现实」，后续为**基础配额 + 自带 API Key**。

## 二、界面与视觉（逐张截图核验）

- **不是纯 2D**：办公室与家具是 **3D 渲染**的纯白极简场景（白桌、黑显示器、带轮办公椅、灰软阴影）；角色是**扁平 2D 矢量**的黑色小马（白眼 + 彩色围巾），像贴纸贴在 3D 场景里。
- **视角**：**斜俯视（约 30–40°）的「剖面娃娃屋」**，无墙无天花板。不是严格等距轴测，也不是正俯视或横版。
- **布局**：左右两列各 4 张工位（含空位）；左墙是茶水区（挂杯架、咖啡机）；另有跑步机健身角与沙发休息区。每个工位上方悬浮名牌（「Marvis 正在执行 1 个项目」「Computer Agent」）。
- **状态动画**：敲键盘干活（头顶任务气泡 / Token 计数）、趴桌打盹冒 z、喝咖啡、健身跑步、打游戏、上厕所/离岗、办公室闲逛。
- **角色区分**：围巾色 + 道具。红 = Team Leader/PM，紫 = 文件，绿 = 电脑，黄 = App，蓝 = 搜索/网页。

## 三、「AI 员工」怎么产品化

- **角色**：出厂预置 6 个固定职责 Agent（PM 总指挥 + File/Computer/App/Browser/Search），零配置；支持自定义管家、导入 Skill、接 MCP/CLI。
- **下达**：单一对话框自然语言，**主 Agent 自动拆解派活**；另有定时任务。**不要求用户画流程**。
- **协作**：多 Agent 并行，PM 统筹避免抢活；文案有「PM 拍了拍 File Agent」的拟人说法，界面靠角色走动与名牌/气泡表达归属。**「起身走到对方工位交办」这一具体动作未确证**——推断目前是闲逛级走位，非语义化交接动画。
- **产物**：每个任务可拉开侧边栏，看步骤、当前由谁执行、中间结果、产出文件/网页预览。

## 四、最接近的参考

1. **AI Town / Smallville**：2D 像素俯视小镇，25 个 agent 自主生活社交。最接近「卡通空间 + 多 agent」的形态原型，但目的是模拟不是交付。
2. **Gather（原 Gather.town）**：2D 像素虚拟办公室，avatar 走近即开启通话，把「空间邻近」直接做成协作机制，商业化最成熟。
3. **Manus**：无空间隐喻，用任务卡 + 步骤时间线 + 虚拟机实时画面表达多步执行。
4. **钉钉 AI 助理**：数字员工长在 IM 与组织架构里，强在权限/审批/通讯录，弱在可视化。
5. **SimTower / 开罗游戏**：等距像素经营模拟，员工在格子里走动、状态肉眼可见；是「办公室拟态 UI」的美学与状态机源头。

**一句话差异**：别人把 agent 藏在日志里，Marvis 把它放进办公室——用「看得见」换信任。

## 五、对本项目的三个直接含义

1. **视觉路线有张力**：Marvis 是「3D 场景 + 2D 角色」，我们的底座是 PixiJS。要么接受纯 2D 等距的差距，要么走预渲染 3D 背景 + 2D 角色合成。见 09 票。
2. **编排可以更简单**：Marvis 用「一个对话框 + 主 Agent 自动拆解」，不要求用户画流程。这和你说的「按预定的编排流程」是两条路，见 08 票。
3. **状态动画清单可以直接抄**：干活 / 打盹 / 咖啡 / 健身 / 打游戏 / 离岗 / 闲逛，外加「头顶气泡显示当前任务与 token」。这是被验证过的状态集合。
