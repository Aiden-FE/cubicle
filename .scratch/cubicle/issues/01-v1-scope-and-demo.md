# 01 — v1 范围与演示剧本

Type: grilling
Status: resolved
Blocked by: —

## Question

v1 到底交付什么？请锁定**一个可复现的演示剧本**（从第一次打开应用到产出第一个结果），并给出明确的「v1 不做」清单。

## 背景

- 目的地是「能直接开工的蓝图」，v1 只做单员工闭环。
- 已选的切片：建企业 → 建项目组 → 空工位 → 招聘程序员 → 派真实任务 → 工位 coding 动画 → 产出可查看。
- 这个剧本会成为后续所有票的验收锚点：领域模型要能表达它，编排模型要能跑通它，可视化要能演出它。**剧本一改，后面全要返工。**

## 要产出

1. **分镜式剧本**：每一步用户看到什么、点什么、系统在后台做什么。
2. **验收标准**：什么算「跑通了」，什么算「失败」。
3. **v1 不做清单**（含理由），并与地图的 Out of scope 对齐。
4. **一个真实任务样例**（用什么仓库 / 什么任务），确保 demo 不是摆拍。

## 候选剧本

- A. 单员工 + 真实代码任务（修 bug / 加小功能），产出 diff。
- B. 单员工 + 办公任务（写一份文档 / 整理一份表格），产出文件。
- C. 单员工 + 研究任务（调研并输出报告）。

## 要逼自己回答

- 观众是谁？你自己，还是要给别人演示？
- demo 多长？3 分钟还是 15 分钟？
- 任务失败时，剧本怎么演下去？
- 「招聘」这一步，是必须点满（选角色、看技能、确认），还是一键录用？
- 第一次打开时，用户面对的是一个空办公室，还是一个「建企业」表单？哪个更有产品感？

## Answer

**结论：v1 = 一段 3 分钟的单员工闭环 demo。任务固定为「给受控小仓库加 CSV 导出功能 + 测试」；成败判据是硬的（测试绿 + diff 可读）；失败也要能入镜。**

五个已拍的板：观众只给自己、任务用受控小仓库、招聘走三步、失败也是内容、砍掉多员工/账号/同步/可视化编排但保留闲时动作。

### 1. 分镜剧本（3 分钟）

| 时间 | 用户看到 / 操作 | 系统在后台 | 镜头焦点 |
|---|---|---|---|
| 0:00–0:15 | 空办公室（娃娃屋视角），4 个空工位，中间浮一张卡：「给你的公司起个名字」 | 创建本地企业记录（无任何网络） | 全景 |
| 0:15–0:35 | 输入「星尘工作室」→ 选模板「软件项目组」→ 办公室落成 | 创建项目组；落地 4 个工位；其中一个高亮「招聘」 | 镜头轻推 |
| 0:35–1:05 | 点高亮工位 → 三步招聘：①角色卡（程序员/产品经理/测试）②能力清单（技能/工具/MCP/模型）③「录用」 | 创建员工实体，装配角色能力包 | 工位 |
| 1:05–1:20 | 角色（阿码）从门口走到工位坐下，显示器亮起，名牌出现；他打个哈欠，摸出手机刷两下 | agent 会话初始化（独立配置目录） | 角色进办公室的第一条动线 |
| 1:20–2:20 | 底部输入框输入任务：「给项目加一个把任务导出成 CSV 的功能，要有测试」→ 阿码头顶「思考」气泡 → 干活蒙太奇：读文件（屏幕滚动代码）→ 写文件（键盘变快，屏幕出现 diff 高亮）→ 跑测试（终端红字）→ 修改 → 再跑（绿字）；**中途起身去茶水间接了一杯咖啡** | pi 事件流驱动一切：`tool_execution_start/read→滚动`、`edit/write→敲键盘`、`bash→终端画面`、`agent_end→完成` | 工位电脑屏幕（这是「看得见」的核心 60 秒） |
| 2:20–2:45 | 工位上方出现「待验收」标记 → 点开任务侧边栏：变更摘要（3 个文件）、测试结果（3 passed）、「查看 diff」「打开文件夹」→ 用户点「通过」 | 产出归档；任务状态机推进到 done | 侧边栏（Marvis 式） |
| 2:45–3:00 | 镜头拉远：办公室全貌，阿码伸个懒腰，掏出手机开始摸鱼 | 任务归档完成 | 字幕：「它不是一个聊天框，它是一间办公室。」 |

### 2. 验收标准（硬判据）

1. 冷启动到录用完成 ≤ 90 秒，全程无需看文档。
2. 任务真实耗时 ≤ 10 分钟；demo 可 2 倍速剪辑。
3. 产出可判：新增/修改文件 + `pnpm test` 全绿（≥3 条）+ `git diff` 可读 + 一键打开产出目录。
4. 动画同步：读/写/执行/测试四类工具状态正确映射；「人在敲键盘但其实在等模型」的穿帮累计 ≤ 3 秒。
5. 失败可见：任何失败都有人话版原因 + 一键重试。
6. 重启不丢：企业 / 员工 / 任务历史在应用重启后完整恢复。
7. 成本可见：任务跑完，侧边栏显示「本任务消耗 token：N」；公司面板有累计（04 票）。

### 3. v1 不做清单

- ❌ 多员工协作、员工间消息、走位交接（→ v2，依赖 08 票）
- ❌ 账号体系（微信扫码 / 邮箱）、跨设备同步
- ❌ 可视化编排画布（→ v2 的雾）
- ❌ 审批/沙箱 UI：v1 只用硬规则「工作区内自由 + 工作区外拒绝」（→ 07 票定细）
- ❌ 插件/市场、角色自定义编辑器
- ✅ 多公司并行与切换（切换不阻塞进行中的工作，程序退出才中断）—— 2026-11-05 修订；运行时语义见 13 票
- ✅ 保留 3 个闲时动作：**喝咖啡、摸鱼看手机、发呆/打哈欠**（它们是「活着」的最低证据，且只是 sprite 状态，边际成本低）

### 4. 任务样例（真实、可重复）

- 仓库：新建 `demo-task-cli`，一个约 30 行的 TypeScript CLI todo 工具（`add` / `list` / `done`），自带 vitest 测试。
- 任务：「给项目加一个把任务导出成 CSV 的功能，要有测试。」
- 通过判据：`pnpm test` 全绿；`todo export --out tasks.csv` 生成合法 CSV；diff 只碰 ≤ 3 个文件。
- 为什么选它：领域小、零外部依赖、失败可回滚（git 一个 commit）、成功可机器验证、10 分钟能跑完。

### 5. 失败分支（必须能演）

- 工位变红、头顶冒「!」气泡；点开：人话版原因（示例：「测试一直不过：export.ts 里日期用了本地时区，测试期望 UTC」）+「重试」+「我来改」。
- 点重试 → 从断点或重新开始，动画重演。
- 这段**不剪掉**：真实感本身就是 demo 的素材。

### 6. 为什么这么切

- 观众是自己 → 不为陌生人做引导层，但保留可录 3 分钟的完成度。
- 受控仓库 → demo 可无限重复，不被真实项目状态绑架。
- 三步招聘 →「预设角色 + 能力清单」是这个产品区别于 agent 套壳的第一差异点，不能省成一键。
- 失败入镜 → 逼着把错误处理当内容做，而不是当 bug 修。
- 保留闲时动作 × 3 → 关掉动画时用户丢的信息，比砍掉它们省的成本更值钱。
