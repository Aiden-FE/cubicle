# 16 — 多员工协作（v2 蓝图）

Type: grilling
Status: closed
Blocked by: 05, 08

## Question

v2 上多员工时：子任务实体怎么从 08 票的 step_plan 升级、谁当经理（PM 预设角色？）、员工之间的消息怎么路由、两个员工抢同一文件的冲突怎么解、「走到对方工位」的动作由什么触发？

## 已定的前提

- 08 已定：规划是展示性字段，v2 升级为可分配的 Task；playbook 与角色建议已分好。
- 03 已定：**pi 无 agent 间消息，协作靠应用层调度器 + 多 AgentSession**。
- 02 已定：员工属公司；任务必有唯一 owner。

## 要拆清楚

- **经理 / 调度循环**：工单进「无主池」？还是必然先给经理？经理是常驻会话还是事件触发？
- **子任务升级**：step_plan 的条目 → Task 的字段映射（验收口径怎么继承？owner 谁拍？）。
- **消息路由**：员工 A 想把结果交给员工 B —— 应用层做消息总线（名字寻址），B 的会话由调度器立项新会话还是 steer 进 B 正在跑的会话？
- **文件冲突**：两人同时被排到同一仓库 → 06 票的 git 边界下用「工位锁」还是「worktree」？
- **走位表现**：「走到对方工位」由消息路由事件触发，还是任务转交事件触发？动画优先级怎么排（09 票状态机的打断规则）？
- **分层**：哪些能力 v1.5（单 PM + 2 员工的小队）就要，哪些真的进 v2。

## 要产出

多员工协作协议（消息、子任务、冲突、走位）、v1/v2 切分、以及 12 票里程碑表里的「多员工里程碑」草案。
