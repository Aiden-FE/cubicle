# 02 — 领域模型与术语

Type: grilling
Status: resolved
Blocked by: 01

## Question

企业 / 项目组 / 工位 / 员工 / 角色 / 能力 / 任务 / 产出 / 会话 —— 这些词各自的边界、生命周期与关系是什么？哪些是**实体**、哪些是**配置模板**、哪些是**运行时状态**？

## 为什么先问

这套词会同时出现在 UI、数据库、agent 的 system prompt 和 IPC 契约里。一个词含糊，后面四处返工。典型歧义：

- 「员工」是招聘时创建的持久实体，还是一次任务执行时的 agent 实例？
- 「角色」是员工的属性，还是可复用的模板（同一个角色可以招多个人）？
- 「工位」是纯视觉位置，还是有状态（占用、设备、当前任务）？
- 「能力」是角色自带的，还是可以单独挂到员工身上？

## 要产出

1. `GLOSSARY.md`：每个词一句话定义 + 它**不是**什么。
2. 实体关系图（文字版即可）：基数与生命周期。
3. 关键不变量：例如「一个工位同时最多一个员工」「任务必须有唯一 owner」「员工必须属于一个项目组」。
4. 用边界场景压测：
   - 员工离职后，工位和历史任务怎么办？
   - 一个人能否同时在两个项目组？
   - 角色定义改了，已招的员工要不要跟着变？
   - 项目组删了，产出文件还在吗？
   - 「员工」挂在公司下还是全局池？同一个人能让两家公司同时上班吗？（多公司并行已定，见 13 票）
   - 「引擎」是员工的一部分、角色的一部分，还是全局设置？（统一协议见 14 票）

## 提示

用 `domain-modeling` skill。术语一旦定下就写进 `GLOSSARY.md`，不要攒着。

## Answer

**结论：公司是绝对容器，员工不跨公司；工位是实体，空位即招聘入口；角色招聘时快照、不传染；任务挂项目组、带 owner 员工；会话与产出都是一等实体；引擎是员工能力配置的一部分。** 术语已落 `GLOSSARY.md`（仓库根）。

### 实体 / 模板 / 运行时三分法

| 类别 | 内容 |
|---|---|
| **实体**（持久，有 id，有生命周期） | Company、ProjectGroup、Desk、Employee、Task、Session、Artifact |
| **模板**（配置，用后即快照） | Role（角色）、Capability（技能 / 工具 / MCP / 引擎 / 模型的统称） |
| **运行时状态**（只记当下） | 员工状态（off-duty / idle / working / paused …）、公司上下班开关、任务状态机（06 票定）、会话状态 |

### 关系与基数

- Company 1–N ProjectGroup（v1 演示只建一个组，模型不设上限）
- ProjectGroup 1–N Desk；Desk 与 Employee 是「占用」关系（0–1），不是从属
- Company 1–N Employee（**员工严格属于一个公司**，不共享、不借调）
- ProjectGroup 1–N Task；Task 必有 owner 员工（v1 下达时必填）
- Task 1–N Session；每个 Session 绑定一个引擎；Task 1–N Artifact
- Role → 招聘 → Employee（快照）；同一角色可在同一公司招多人，坐不同工位

### 关键不变量

1. 一个工位同一时刻最多一个员工。
2. 员工必须属于一个公司，且只属于一个。
3. 任务必须属于一个项目组，必须有唯一 owner 员工。
4. 会话必须属于一个任务，绑定一个引擎。
5. 产出必须属于一个任务。
6. 角色定义改动**不传染**已招员工（快照）。
7. v1 只有「归档」，没有「删除」：员工离职、项目组 / 公司下线都归档，历史全保留。

### 边界场景裁定

- **同一个员工在两个项目组**：允许 —— owner 是任务级字段，员工可以被多组任务的指派；但工位与雇佣关系仍唯一归属公司。员工不属于某个项目组。
- **角色改了**：已招员工不变；想要新配置 → 用同角色再招一个人，或（v1.1 雾）做「手动同步到最新角色」。
- **员工离职**：归档；工位清空；任务、产出、会话全保留，履历从任务反查。
- **两家公司同时上班**：互不影响；并发与隔离语义在 13 票。
- **「引擎」归属**：员工能力配置的一部分（招聘时由角色给默认值，员工级可改）；协议与对等矩阵由 14 / 15 票定。
