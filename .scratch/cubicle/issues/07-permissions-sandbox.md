# 07 — 权限、审批与沙箱

Type: grilling
Status: resolved
Blocked by: 06

## Question

agent 执行 shell、写文件、联网、装依赖、调外部 MCP 时，**哪些要审批、谁来批、怎么批**？v1 的沙箱边界在哪？

## 为什么现在问

这是「数字员工」和「玩具」的分水岭：批得太严，员工什么都干不了；放得太松，一次误删就是灾难。审批 UI 还会直接影响工位动画 ——「举手等批准」是不是一个状态？

## 要拆清楚

- **风险分级**：读文件 / 写工作区内 / 写工作区外 / 执行命令 / 联网 / 装包 / 调外部服务。
- **审批粒度**：每次？每类？每个任务开头一次性授权？
- **审批 UI**：在哪弹？工位上要不要有「等待批准」的表现？
- **git 分级**（06 票已定员工自主 commit、应用对 git 只读）：commit 必须可；push / `reset --hard` / 删分支等高危动作在这里分级——默认倾向：push 禁、破坏性禁。
- **沙箱**：v1 要不要 OS 级沙箱（Windows 上成本高）？还是只做工作区边界 + 命令白名单？
- **回滚**：写坏了怎么恢复（git 快照？文件备份？）

## 要产出

风险分级表、默认策略、审批交互、沙箱方案、回滚方案。

## 一个必须回答的问题

v1 自用，你愿意让 agent 在你真实的工作目录里跑 `rm` / `git reset` 吗？如果答案是不，那默认策略就是「工作区外一律拒绝 + 命令白名单」，这会显著改变 06 的工作区设计。

## Answer

**结论：v1 没有正式审批系统 —— 硬规则策略表自动执行；违规「拒绝可见」（结果回传 + 工位气泡 + 任务流水）；agent 被拒可在会话内自然请示，用户用 steer 批（自然语言审批）；不上 OS 级沙箱，工具级策略 + bash 黑名单，承认 bash 是结构性溃点（风险入 12 票表）。**

### 1. 谁来批

- **机器批**：策略表在**适配层**执行（14 票协议的一部分）—— 内置 edit / write 直接拦截；bash 走黑名单。拒绝不弹卡。
- **人批**：只有一条渠道，对话 —— agent 被拒后可以在会话里请示（「我想 push，被公司政策拒了，可以吗？」），用户 steer 回复（08 票已定 steer 即时生效）。**自然语言就是审批**。
- 弹卡式审批 UI → v2（和 16 票协作系统一起设计）。

### 2. 默认策略表（已确认）

| 动作 | v1 策略 | 说明 |
|---|---|---|
| 读（工作区内 / 外） | 允许 | 只读不惧 |
| 写工作区内 | 允许 | 自主区 |
| 写工作区外 | **拒绝** | 含 `~/.pi`、`~/.codex`、其它应用目录 |
| bash | 允许 + 黑名单 | 拒：git push / reset / 破坏性 checkout / rm -rf 家目录与系统路径 / 关机重启 / 写工作区外的 curl |
| git | add / commit / status / diff / log 允许 | push 拒、`reset --hard` 拒、删分支拒（06 票哲学：回滚也派任务） |
| 网络 | 允许 | 引擎自身 API + 公开读取；自用机器的现实 |
| 装依赖（工作区内 pnpm/npm install） | 允许 | demo 不用，但不设卡 |
| MCP 外部调用 | 允许，白名单制 | 只能调用户在引擎中心配置过的 server（05 票） |
| 模型成本 | 软闸（04 票） | 硬闸 = 审批式，v2 |

### 3. 违规表现（拒绝可见）

拒绝文本**回进工具结果**（agent 能读、能绕路或请示）+ 工位冒「被拦」气泡（动画归 09 票）+ 违规记录进任务流水（复盘可见）。

### 4. 沙箱边界（诚实的限界）

- v1 不上 OS 级沙箱（AppContainer / Job Objects）—— 自用性价比低。
- bash 是结构性漏洞（任意命令可写工作区外）：黑名单缓解 + 引导 agent 优先用内置工具；信任模型 = 自用机器。
- 这条风险及其触发信号（策略击穿事件）写入 12 票风险表。

### 5. 与其它票的对接

- 05 票 manifest 的 tools 开关 × 07 票策略表 → 装配期生成**逐员工最终 policy**，随会话生效。
- 引擎启用时跑**准入探针**（14 票已提）：给引擎一个含「明确拒绝」的最小任务，验证拒绝是否被遵守且可见。
- 「被拦」是新增动画状态 → 09 票状态清单。
- 违规流水的落库 → 11 票 schema。
- 用户请示的 steer 交互 → 10 票。
