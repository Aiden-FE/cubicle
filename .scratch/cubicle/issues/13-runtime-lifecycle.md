# 13 — 运行时生命周期：多公司、上下班与优雅暂停

Type: grilling
Status: resolved
Blocked by: 02, 06, 14

## Question

**多公司并行、切换不阻塞、上班激活、下班优雅暂停、程序退出才中断** —— 这五个行为的确切语义是什么？尤其是「优雅暂停」在 agent 引擎层面怎么实现、恢复时从哪继续？

## 用户已定的行为（不再重开）

- 公司不只有一个，用户可切换公司。
- **切换不阻塞进行中的工作**：切走公司后其员工继续干活；只有程序退出才中断。
- 公司可执行「上班 / 下班」：上班 → 未完成任务的员工激活开工；下班 → 各工作中的员工**优雅暂停**任务。

## 要拆清楚

- **多公司并行**：两家公司同时「上班」的并发上限？工作区 / 会话 / 密钥怎么隔离？切换走后原公司有人在干活，UI 怎么呈现（后台指示器？托盘角标？）。
- **上班**：触发方式（手动按钮 / 打开应用自动 / 定时）？激活的是「全部员工」还是「有未完成任务的员工」—— 用户原话是后者，但要确认空闲员工是否也算「解除下班态」。
- **下班（优雅暂停）**：让当前 tool call 跑完再停，还是立即中断循环？被暂停的会话上下文、任务状态、写了一半的文件怎么落盘？恢复时是「同一会话续跑」还是「新会话重述任务」？agent 正在等模型响应时下班的处理？
- **退出中断**：程序退出是等任务跑完才退，还是与「下班」同机制落盘暂停？崩溃后的恢复语义与 11 票合流。
- **引擎差异**：按 14 票的统一协议，各引擎「暂停 / 恢复 / 取消」能力不对等 —— 协议必须给最低承诺（至少：取消 + 状态落盘）与降级策略。
- **表现层**：下班的员工收工动画 / 工位关灯，上班时开机灯亮 —— 与 09 票的状态机对接。

## 要产出

公司 / 员工 / 任务三层状态机（含 paused、下班态）、暂停与恢复的引擎级方案与最低协议承诺、退出语义、切换公司的 UI 呈现约定、「上下班」是否进 3 分钟 demo 的决定。

## Answer

**结论：定时上下班为主（公司级时间表 + 开机补触发 + 手动即时 override）；下班 = 90s 宽限 + 全量落盘 + 可恢复（pause 不支持的引擎降级「跑完再停」）；程序退出三选对话；崩溃恢复由用户主动选；跨公司全后台可见，运行时与视图彻底解耦。**

### 1. 三层状态机

- **公司**：`上下班状态位` + **时间表**（`on: "09:00" / off: "18:00"`，每公司独立）+ **即时 override**（forceOn / forceOff，一次性，不改表）。
- **员工**（动画层 09 票）：`offDuty → idle → (走位/活) → paused`；paused 分 reason：`offduty | budget`（04 票软闸共用同一标志）。
- **任务**（06 票）：五态 + 正交 paused 标志；会话（per 06/14）持有恢复指针。

### 2. 上班（已拍板：定时触发）

- **触发**：应用运行中的本地分钟级时钟到点 → 公司转「上班」→ 激活本公司**有未完成/可恢复任务**的员工开工或续跑。
- **开机补触发**：应用晚于上班点启动 → 打开即自动补一次上班（窗口内）。
- **即时 override**：状态胶囊点按 = 立即上班 / 立即下班（一次性动作）—— v1 必备：demo 与「现在就想让它动起来」不依赖时间表。时间表未配置的公司默认「待机」，override 即唯一入口。
- 激活顺序：先「恢复中断/paused 任务」，再领「待办」—— 不抢跑（08 票规划调用先行）。

### 3. 下班（优雅暂停三拍）

1. **宽限 90s**：停发新工具调用；在跑的当前 call 跑完或到 90s 强制切段。
2. **落盘**：会话 transcript（engines 私有目录）、任务 `paused:offduty`、写一半的文件注明「下班暂停」（工作区文件保持原样，06 票 git 只读不变）。
3. **可恢复**：引擎 `pause: supported`（12→14 协议声明）→ 续跑（`--resume` / 会话树）；不支持 → 「跑完再停」降级 + 下次上班走「新会话重述任务」（14 票已定）。
- 动画：工位灯暗、显示器缓灭、员工收工（09 票状态表）；resume 后灯亮恢复原有姿态。
- **验收提示**：进 01 票 demo 的可选拍点 —— override 演示（点下班 → 暂停 → 点上班 → 续跑）约 20 秒，可插在验收镜头后。

### 4. 多公司并行

- 每公司独立：会话池 / 工作区 / API key（02 票隔离）；**程序退出前任何切换都不触碰运行中会话**。
- 并发闸：适配层每公司会话并发上限（默认 3，v1 实际=1；为 v2 多员工留位）。
- 跨公司呈现（已拍板）：左轨头像角标「N 活跃」；全局 toast 带公司名前缀（完成/失败/请示跨公司照样弹）；办公室动画照常在后台申请画布权重。

### 5. 退出（已拍板：三选对话）

`直接退出（= 对所有在跑任务执行一次「下班」并落盘）` / `等全部完成再关` / `取消`。与下班共用同一机制，不另造"强杀"路径（崩溃除外）。

### 6. 崩溃恢复（已拍板：用户主动选）

重启后列「中断的任务」面板：**续跑**（引擎支持 resume 时）/ **重开**（新会话重述）/ **放弃**（进失败归档）。不静默自动续跑。
