# 05 · 首切片与验收

Type: grilling
Status: resolved
Blocked by: 01, 02, 03, 04

## 问题

第一个 tracer bullet 切在哪？三条候选：只证「技能能进引擎」（不碰 UI）／学院 UI 先行（引擎先不消费）／全链路最小。

BOSS 选了**全链路最小**。风险是它很容易变成「把整张蓝图做一遍」，所以本票的职责是把它**收窄到真的能一次做完**。

## Answer

**全链路，但宽度收窄到极限：**

- **1 个被下发的角色**（新建，如 `academy-slice`）+ **1 个对照组角色**（复用现成的 tester）
- **1 个技能**（fixture 里写死一个暗号，如 `ACADEMY-7`）
- **1 个引擎**：pi（唯一的进程内 SDK，装配路径最短）
- **1 名主员工 + 1 名对照员工**（对照组是为了反向断言，不是第二个被下发的角色）
- **迁移只做最小版**：`role` 表读 Neo 角色目录并缓存（一读一写），旧的 `role_snapshot` 保留读取兼容

**链路（每步都必须真发生，不许 mock 掉中间环节）：**

1. 学院浮层里「装」：`neo add <fixture 路径> --role academy-slice`
2. 学院里看到它（名字 / 来源 / hash）
3. 下发给 `academy-slice`
4. 招聘 `academy-slice` → 员工 A；招聘 tester → 员工 B
5. 给 A、B 派同一句话
6. 引擎根里：A 有 `agent/skills/<name>/SKILL.md`，B 没有
7. mock 模型 server 记录的请求：A 的上下文含 `ACADEMY-7`，B 的不含

**验收一条命令**：`npm run build:renderer && npm run e2e:15`

（编号核对：现有 `e2e:02`–`e2e:14`，15 是下一个空位。）

**断言点必须在「引擎真正消费」的那一层**，不是「文件躺在盘上」：

- 文件层：A/B 的员工根目录对比；
- 契约层：mock server 收到的是**真实的 system prompt / skill 清单**，断言 `ACADEMY-7` 在其中（正向）且不在 B 中（反向）；
- 不许让模型「自觉复述暗号」来验收 —— 那测的是模型，不是装配。

**单测（不进 e2e，但同票交付）**：

- 装配函数：`default ∪ domain ∪ role`、同名归属；
- `role_snapshot` 新结构 + 旧结构读取兼容（`store.test.mjs` 现有迁移测试的同一套路）；
- `employees.role_snapshot` 写入时不复制技能内容，只写 hash。

## 为什么这样切

- 「只证技能能进引擎」会留下一个不可见的坑：装配代码没有 UI 触发路径，等于纸上跑通。
- 「UI 先行」正是 `skills` 字段变成死字段的原因 —— 展示层先行、消费层永远没到。
- 全链路是对的，但必须只有一条链：两个对照员工是**验证隔离**的最小代价，再多一个角色就是在做发布而不是切片。

## 这条 e2e 不算完（写在票里防自欺）

- 它只跑 pi；codex / dsh 的装配由后续实现票各自补 e2e。
- 它只跑 1 个技能；「同名不同版本不撞」需要另造一个双版本 fixture。
- 它不验 MCP；MCP 的首次确认与来源标记另验。
- 它不验「升级已招员工」；钉 hash 的升级路径另验。
