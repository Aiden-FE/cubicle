# 02 · 隔离与版本

Type: grilling
Status: resolved
Blocked by: 01

## 问题

「角色间的技能隔离」有四种不同的东西，成本差一个数量级：上下文隔离（看不见）、依赖隔离（同名不同版本不撞）、执行隔离（技能自带代码按角色独立进程）、全部。

版本这一侧同样要拍：招聘时把技能**内容快照**进员工（现状语义）／**钉版本**（记 `skill@hash`，运行时解析）／**活引用**（学院一改全员跟着变）。

## Answer

**隔离 = 上下文隔离 + 依赖隔离，边界是角色。**

- **上下文**：员工的引擎只看得见自己角色的资源；别的角色/别的公司的资源不出现在 prompt、工具列表、技能目录里。
- **依赖**：同名技能的不同版本各装各的目录，互不覆盖。
- **执行隔离不做**：技能自带的脚本 / MCP server 仍按现状由引擎拉起；`05 票` 的「tool 代码不开放」不动。
- **边界是角色不是员工**：同角色两名员工共用同一份装配结果（招两个程序员 = 两个用同一套技能的人）。

**版本 = 钉 hash，内容不复制。**

- 招聘时记录 `locks{skill: sha}`（Neo 的 `state/locks/<role>.yaml` 已经是这个形态）；
- 学院里**已发布的版本永不改写**，修 bug = 发新版本；
- 升级 = 显式动作（对已招员工重钉），不自动传染；
- 老员工的「钉住」的是一组 hash，不是一份拷贝 —— 所以学院的旧版本必须留着。

**废除公司级能力覆盖**：05 票的三层作用域收缩为「角色（学院）+ 员工（招聘时钉版本；之后可改引擎 / 模型）」。

## 为什么

- 上下文隔离是员工「串味」的唯一根因：`~/.agents/skills`、共享的 `DSH_HOME`、codex 的全局技能，任何一条漏进去，隔离就是假的。
- 依赖隔离不做，两个角色要同名技能的不同版本时会互相覆盖 —— 这是「学院」最容易在三个月后炸的地方。
- 执行隔离在 v1 没有收益：MCP 已经被判给用户自负审查（见 04 票），剩下的「技能带代码」正好是 05 票否决掉的那类东西。
- 钉 hash 而不是钉内容：既保住「不传染」，又让学院能集中修 bug；代价是版本必须不可变，这条必须写死在实现里。

## 已知缺口（实现票必须修）

- **dsh 的 `DSH_HOME` 是全体员工共享的**（`engines/dsh/home`，`dsh/adapter.mjs:48`）—— 往里放技能就是全员共享。要么拆成每员工 home，要么用 `customSkillDirs` 只放该员工的路径。
- **pi SDK 会额外读 `~/.agents/skills`**（走 `HOME`，改 `agentDir` 管不到）—— 必须传 `noSkills:true` + `additionalSkillPaths`，只喂该员工那一份。
- **codex** 读 `$CODEX_HOME/skills/`，天然按员工隔离，但要注意它在 `skills/.system` 下自建的内置技能。

## 被否掉的

- 内容快照（A）：学院修好的 bug 永远进不到老员工，除非重新招人。
- 活引用（C）：学院一改，全公司员工的上下文同时变，事故无法复现。
- 公司级覆盖：v1 单机自用，收益接近零，维护成本是三层合并 + 同名灰牌 UI。
